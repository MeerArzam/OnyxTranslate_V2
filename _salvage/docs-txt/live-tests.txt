What this test is

Every language in this report was put through a REAL Gemini round-trip using the exact
production pipeline — not a mock, not a static simulation:

Exact production system prompt — buildSystemPrompt() from
convex/translateContent.ts: all 23 phases (P1 glossary fidelity → P23 final proofread),
per-language dialogue marks, profanity map, rank map, magic-system note, formality system, style
sheet, locked glossary column, and name map.

Bible Pass glossary lock — applyBiblePassServer() wraps locked terms in
placeholders before Gemini sees the text; postProcessTranslationForTest() restores them,
so Signet/Venin/Wards/Empyrean and friends can never be re-translated ad hoc.

Same Gemini endpoint & 5-key rotation — native
generateContent API, thinkingBudget: 0, 3 attempts per key, 429/5xx backoff.

Same post-processing — placeholder restore, dictionary-format normalization,
meta-commentary stripping, paragraph-label stripping, cultural filters, dragon-telepathy formatting,
RTL marker insertion.

Full 23-phase QA engine — runQA() from src/lib/translator/qa.ts,
plus P2 locked-name spot checks (Violet / Xaden / Aretia) and P8 script/RTL verification.

How to run it

Open /#/overview → click ⚡ Live Tests → Run all 20 tests.
Each language runs as its own Convex scheduled action (2s spacing, server-side chaining), so the suite
survives page closes, action timeouts, and per-key rate limits. Results stream in reactively.
Backend: api.liveTest.runAllLiveTests → api.liveTest.runLiveTestLanguage
(imports the real production exports from translateContent.ts; results persisted to the
liveTests table via liveTestStore).
