2. Session Isolation Model

Every browser tab generates a unique sessionId on mount
(useState(() => { ... }) in src/pages/Translator.tsx —
persistence via sessionStorage). All client-facing Convex queries filter by it,
so two tabs (or a private window) never see each other's progress. Imported projects are
assigned the importing session's ID.

The session check lives server-side in convex/queries.ts:

```
export const getProject = query({
  args: { projectId: v.id("projects"), sessionId: v.string() },
  handler: async (ctx, args) => {
    const project = await ctx.db.get(args.projectId);
    if (!project || project.sessionId !== args.sessionId) return null;
    return project;
  },
});
```

Auto-resume uses the latest project for the session:

```
export const getLatestProject = query({
  args: { sessionId: v.string() },
  handler: async (ctx, args) => {
    const projects = await ctx.db
      .query("projects")
      .withIndex("by_session", (q) => q.eq("sessionId", args.sessionId))
      .order("desc")
      .take(1);
    return projects[0] ?? null;
  },
});
```

3. End-to-End Data Flow

3.1 PDF upload & parse

handleFileSelect (Translator.tsx) &rarr; parsePDFHeader reads page count
without decoding pages.

parsePDFBatch loops in batches of PARSE_BATCH_SIZE = 10 pages, updating
setParseProgress({ current, total }) after each batch (live "Page X of Y").

storePdfAction → convex/upload.ts storePdf stores the original PDF in
Convex File Storage, returns storageId.

parsePdfAction → convex/parsePdf.ts parseUploadedPdf re-parses
server-side with pdfjs-dist, groups text items into lines by Y-coordinate (2 px tolerance) —
fixes broken words/missing letters.

createProjectMutation writes the projects row
(fullText, pageData, pdfStorageId, status: "ready").

3.2 Text paste

setSourceText(text) directly; project row is created lazily inside
startTranslation with fileName: "Pasted Text".

3.3 Translation (Begin Translation Journey)

startTranslation creates the project if needed, then calls
translateLanguageAction({ projectId, langCode: langs[0], marketContext, nextLangCode: langs[1],
remainingLangs: langs.slice(2) }).

convex/translateContent.ts translateLanguage: chunks
project.fullText into 2,500-word chunks, and for each chunk runs:
sliding-window context (last 2 sentences of previous chunk) &rarr; Bible Pass
(glossary terms replaced by __PH0__ placeholders) &rarr; Gemini call
(5-key rotation, retries) &rarr; placeholder restore &rarr; cultural filters &rarr;
dragon-telepathy formatting &rarr; RTL marker &rarr; runQA &rarr; writes the
chunks row and bumps translations.completedChunks.

After the last chunk the action merges text into translations.mergedText, marks
the language complete, and chains the next language via
ctx.scheduler.runAfter(0, api.translateContent.translateLanguage, { ... }).

The browser can close at any point — the chain is server-side. Progress is read back
through reactive queries (getTranslationProgress, getLivePreviewText).

3.4 PDF generation (autonomous)

When a language finishes inside the scheduler queue
(convex/translateQueue.ts processLanguage &rarr; status
"generating_pdf"), convex/generatePdf.ts generateTranslatedPdf loads the
original PDF from storage, copies each page, whites out text using per-text-item coordinates
(preserving images/maps), overlays the translation with Noto fonts for non-Latin scripts
(Helvetica fallback), stores the PDF, and either chains the next language or, when none
remain, sets projects.status = "all_translated" and schedules
zipAssembly.buildZip.

3.5 ZIP assembly

convex/zipAssembly.ts buildZip downloads every completed
translations.pdfStorageId, bundles them (plus translation_report.txt)
with JSZip, stores the ZIP, and writes projects.zipStorageId/zipUrl and
status: "complete".

3.6 Images

translateImageMultiLang (client) downsamples to ≤1024 px JPEG
&harr; convex/translateImage.ts translateImage sends the base64 image to Gemini
multimodal for OCR + translation in one pass, saves to imageTranslations.
